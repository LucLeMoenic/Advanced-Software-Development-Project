# Budget & Expense Tracker Architecture and Data Design

## Individual Service Architecture

```mermaid
flowchart LR
    U[Traveller] --> S[Shared Vue frontend :5100]
    S -->|/budget/| F[Student 4 frontend<br/>nginx + HTML/CSS/JS/HTMX]
    F -->|/budget-api/*| B[Student 4 backend<br/>ASP.NET Core 8]
    B -->|typed HTTP CRUD| D[Student 4 database API<br/>ASP.NET Core 8 + EF Core]
    D --> Q[(SQLite budget.db)]
    B -->|strict JSON request| O[Shared Ollama]
    O --> L[Approved Llama model]
```

Only the database service references EF Core SQLite or opens the database file.
The backend owns all authoritative conversion, dashboard, and insight
orchestration. The frontend calls no database or model endpoint directly.

## Conceptual Model and ERD

A journey label groups one or more category budgets. A budget owns zero or more
expenses. It is local text, not a relation to another feature.

```mermaid
erDiagram
    BUDGETS ||--o{ EXPENSES : contains
    BUDGETS {
        integer id PK
        text journey_label
        text category
        integer limit_amount_minor
        text base_currency
        text start_date
        text end_date
        text created_at
        text updated_at
    }
    EXPENSES {
        integer id PK
        integer budget_id FK
        text description
        integer original_amount_minor
        text original_currency
        integer converted_amount_minor
        integer conversion_rate_scaled
        text rate_as_of
        text spent_on
        text notes
        text created_at
        text updated_at
    }
```

## Logical and Physical SQLite Design

```mermaid
flowchart TB
    JL[journey_label TEXT<br/>trimmed 1..80] --> BU[budgets]
    CAT[category TEXT<br/>allow list] --> BU
    LIM[limit_amount_minor INTEGER > 0] --> BU
    CUR[base_currency TEXT length 3] --> BU
    PERIOD[start_date/end_date TEXT<br/>end >= start] --> BU
    BU -->|UNIQUE journey/category/period| UI[unique index]
    BU -->|id ON DELETE CASCADE| EX[expenses]
    EX --> AMTS[original/converted INTEGER > 0]
    EX --> RATE[rate_scaled INTEGER > 0<br/>rate_as_of TEXT]
    EX --> SPENT[spent_on TEXT]
    EX --> IDX[index budget_id + spent_on]
```

- SQLite integer primary keys are positive and generated by the provider.
- Currency amounts are stored as integer minor units; rates are scaled by
  100,000,000 to preserve a deterministic snapshot.
- Dates use ISO `yyyy-MM-dd`; UTC timestamps use provider-supported UTC values.
- API validation enforces cross-row rules: one base currency per journey and
  expense dates within the parent budget period.
- Check, unique, foreign-key, and journey-currency triggers provide an atomic
    database enforcement layer.
- Startup applies migrations and an idempotent transaction creates 12 budgets
  and 24 expenses when their stable sample keys are absent.

```mermaid
flowchart TB
    H5100[Host :5100] --> SF[shared-frontend :80]

    SF -->|/budget-api/| B[student4-backend :8080]

    H5204[Host :5204 diagnostics] --> B
    H5304[Host :5304 diagnostics] --> D[student4-database :8080]
    F --> B
    B --> D
    D --> V[./student-4/database/storage<br/>/data/budget.db]
    B --> O[ollama :11434]
    MS[ollama-model-setup] --> O
    AL[shared agentic-loop] --> O
```

Database health gates backend startup; completed model setup and database
health gate the normal backend; backend health gates the frontend; Student 4
frontend health is added to the shared frontend dependency set.
