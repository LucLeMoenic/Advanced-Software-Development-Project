# Travel Logistics & Advisory Service - Risk Plan

Student 5 (Alex Chen), Release 0. Likelihood and impact are scored 1-5;
score is likelihood x impact.

| ID | Risk | L | I | Score | Mitigation | Current status |
|---|---|---:|---:|---:|---|---|
| TL-R01 | The model invents a visa or entry rule that is not in the stored data. A wrong border rule is the most damaging output this feature can produce. | 4 | 5 | 20 | The advisory is grounded: `advisory.build_prompt` pastes the destination row, weather notes and transit options into the prompt verbatim and instructs the model that every fact, number and length of stay it states must appear in that recorded text. Sections with no rows must be declared as empty rather than filled in. A Smartraveller disclaimer is rendered as markup in `advisory_result.html`, so it appears whether or not the model complies. Grounding is asserted in `backend/tests/test_advisory.py`. | Mitigated, with a known residual - see `known-issues.md`. During development the model twice added a passport-validity rule belonging to a different destination; a *negative* instruction made it worse, and a positive "every number must appear above" constraint removed it. Occasional low-severity drift is still possible. |
| TL-R02 | Ollama is unavailable, cold, or too slow during the demonstration, and the advisory panel appears to hang. | 4 | 4 | 16 | Three layers. `ollama_client` bounds the call at 120s and turns every failure into `OllamaUnavailable`; nginx allows 180s on `/ui/` so the proxy never cuts a live generation short; the fragment route renders "The travel adviser is unavailable right now" at 200 so HTMX actually swaps it. For the wait itself, `formatElapsed` counts seconds up and switches to "still working - Ns" past 45 seconds, so a slow answer does not read as a hang. | Mitigated and tested. The read-only panels are unaffected by an Ollama outage, so the feature still demonstrates without a model. |
| TL-R03 | A dependency failure leaves a stale "Loading..." on screen and the traveller believes the data shown is current. | 3 | 4 | 12 | Two paths, because there are two kinds of failure. Failures the backend sees are rendered as 200 fragments by blueprint-scoped error handlers in `ui.py`. Failures it never sees - its container down, nginx answering 502 - are caught by the `htmx:responseError` listener in `index.html`, which writes the same `.fragment-message` markup so both look identical to the reader. The `<select>` case is handled separately because a `<p>` is not valid inside a select. | Mitigated in source and covered by fragment tests. |
| TL-R04 | The backend forwards a database 5xx verbatim, so the frontend cannot tell a backend fault from a dependency fault. | 3 | 3 | 9 | `relay()` forwards status codes deliberately, which is right for 4xx (a 404 is a real answer) but means a database 500 arrives at the frontend indistinguishable from a backend 500. The reader is protected by the fragment layer, which shows a readable notice either way; only an operator reading the JSON API is exposed. | **Accepted for Release 0**, recorded in `known-issues.md`. The fix - reserving 502 for "my dependency failed" - is a one-line change in `relay()` plus test updates, deferred rather than done because it changes the passthrough contract other students may already be reading. |
| TL-R05 | Seed data is duplicated or destroyed on container restart, so the demonstration starts with a corrupt database. | 2 | 4 | 8 | `init_db` runs `schema.sql` with `CREATE TABLE IF NOT EXISTS`, then counts `destinations` and executes `seed.sql` **only when that count is zero**. The seed uses explicit ids, which is safe precisely because it can only ever run against an empty table. The file lives on a bind mount (`student-5/database/storage:/data`), so it survives `docker compose down` as well as a restart. Each pytest test gets its own file through `tmp_path`, so the suite never touches the real database. | Mitigated. Restart-idempotency is a property of `init_db` and holds by construction. |
| TL-R06 | A small reviewer model produces malformed or ungrounded review output, and the agentic-loop evidence is unusable or - worse - a fabricated finding gets accepted into the code. | 4 | 4 | 16 | Two controls. Machine-side, `ParseVerdict` in `AgenticLoopApplication.cs` rejects a review that lacks the `[OBSERVE]` header, omits a required section, or pairs a REQUIRED finding with an ACCEPT verdict, and requests one format correction. Human-side, the Adapt phase is an explicit human decision, not an automatic apply. Prompt-side, `docs/prompt-library/reviewer-llama32-v2.md` replaces the shared prompt's fill-in template with prose. | Mitigated and demonstrated. On the successful run the reviewer produced exactly this failure - a REQUIRED finding copied from the prompt's worked example, describing a division-by-zero that does not exist in the proposal - and both controls caught it. See `review-record.md`. |

## Risks retired during the build

| Risk | How it was retired |
|---|---|
| The frontend needs CORS on every fragment endpoint. | nginx proxies `/ui/` and `/api/` so the backend is same-origin; no CORS anywhere. |
| A CDN version bump silently changes HTMX under the page. | HTMX pinned to 1.9.12 and locked with a `sha384` Subresource Integrity hash. |
| `destination_id` from a form or JSON body steers the database URL (`1/../weather-notes/1`). | `advisory.parse_destination_id` coerces to `int` at the boundary before the value reaches any URL. The CRUD routes were never exposed, because Flask's `<int:row_id>` converter had already done it. |
| nginx caches the backend hostname and goes stale when the container restarts on a new IP. | `resolver 127.0.0.11` plus a variable in `proxy_pass`, so the name is re-resolved per request. |
| A shared stylesheet path that does not exist in the image breaks the page in CI. | `shared/style.css` references removed from Student 5; the frontend ships its own `style.css`. Commit `9e894c9`. |
